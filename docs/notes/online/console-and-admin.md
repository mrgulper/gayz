# Firestore read limit, Console admin tools, feedback/alerts, owner drop-in, Hall of Fame

Split out of the old `online.md` on 2026-11-13 (word for word, oldest first). Add new notes at the end.

**Firestore free read limit (2026-11-09)**: the 50k/day free reads ran out on 2026-11-07 and again 2026-11-08. Causes found: (1) every Playwright test page read the live database (~17 calls a page: Market, clans, top 3, Map of the Week, online count) - ~230 tests a run, several CI + local runs a day. `playwright.config.js` now maps the Firestore/Auth hosts to nothing (`--host-resolver-rules`), for every context; online tests use the in-memory fakes. (2) Every real visit preloaded the Market (up to 300 reads) and the clan ranking (a read per clan + one per member) at startup. The Market now loads when opened; the clan ranking shows the copy saved on the device (`gayz-clan-ranking`, cleaned on read) and loads fresh when General opens, at most every 15 min (`_clanRankingDirty` forces it after your own clan changes). (3) Map of the Week kept an empty answer (saved while reads were refused) for 12h - empty answers now last 30 min. Servers use the Realtime Database (separate quota), not Firestore. Firestore quota resets at midnight Pacific.

**Watching the read count (2026-11-12)**: the private Console's Menu has a Health section (gayz-console `api/health.js`) showing today's reads vs 50k, the reset time and a pace forecast, orange from 70% / red from 90%, with a dot on the Menu button. It reads Google Cloud Monitoring's `firestore.googleapis.com/document/read_count` using `MONITORING_KEY` on the console's Vercel project - a separate `console-health` service account with only "Monitoring Viewer". `FIREBASE_SERVICE_ACCOUNT_KEY` here gets 403 from Monitoring (no role), and it's a full admin key, so it was deliberately not copied to the console. If the counter or Map of the Week vanish, check that panel first.

- **Console admin controls (2026-11-12, Console batch 4).** `api/_lib/admin.js` (rules, tested in `tests/servers.spec.js` on `fakeServerDb`) behind two doors: `api/live.js` (public: `{pid}` -> banner/events/hidden maps+builds/own ban; `{action:'report'}` -> player report, one per reporter per target per 6h) and `api/admin.js` (the Console only: header `x-admin-secret` must equal Vercel env `ADMIN_SECRET`, >= 16 chars, on BOTH the game and gayzconsole projects; the Console's own server adds it, its page never sees it). Everything is in the **Realtime Database** (`liveConfig`, `bans`, `playerReports`, `reportLimits`, `reportsSeen`, `serverPids`) - no Firestore reads, no rules paste. Map/build reports are read from Firestore over REST (`api/_lib/firestoreRest.js`, collection-group query on `reports`); "Hide" never deletes, it adds the id to `liveConfig.hidden` and `CloudSync.fetchSharedMaps/fetchSharedMap/fetchCommunityBuilds` drop it. Kick/ban is by **Player ID** (`settings.playerId`): `myDetails()` sends `pid` on create/join, `serverPids/{server}/{slot}` maps slot -> Player ID, `createServer/joinServer` throw 403 `banned`. "Just kick" = a 2-minute ban (`KICK_MINUTES`) so PlayNet's automatic `_rejoin` doesn't put them straight back. Chat bans are **client-side only** (`banMessage()` in both send functions) - same trust model as the spam mute; servers are enforced server-side. Client: `src/game/LiveConfig.js` asks 1.5s after boot, every 2 min while visible and on tab focus, caches the answer in `gayz-live-config` (first paint), fires `gayz-live` on change (theme month, bg mood, snow listen). Holiday switch = `holidayDate()` used as the default date by `monthIndex`, `pictureThemeFor`, `holidayFor`, `winterOn`, `_applyBgMood`. Test seam: `window.__liveConfigForTests` + `await game.__liveAsk()`.
- **Console Safety batch (2026-11-12).** Same two doors. `liveConfig.off` = feature off-switches (`SWITCH_IDS`: online, chat, market, sharing, gallery, leaderboards): `LiveConfig.switchedOff(id)` guards `CloudSync` market/sharing/gallery/leaderboard calls (throws `code: 'switched-off'`; list loads are `quiet`, actions toast after 300ms so they land after the caller's own error toast) and both ChatUI send functions; the banner shows "Paused:" chips. `liveConfig.maintenance {on,text,at}` = full-screen `#maintenance-screen` over the homepage only (never inside an iframe = the Console preview; a running game gets one toast), polled every 30s while on. `onlineClosed()` makes `createServer/joinServer` throw 503 `switched-off` for both. Every Console change writes `adminLog` (last 300) through the `ADMIN_ACTIONS` wrapper; `backup` returns `{gayzBackup:1, at, data}` of `BACKUP_PATHS`; `restore` replaces all of them except `adminLog`. Tests: "admin safety" + "live config: paused features" in `tests/servers.spec.js`.

- **Console Live events batch (2026-11-13).** Same two doors, all inside `liveConfig` (so Backup/Restore already cover it): `schedule/{id}` `{what, start, end, pct}` (calendar; `what` = an `EVENT_IDS` id, `halloween`/`christmas` or `sale`, max 31 days, 50 entries, ended ones listed 1 day then tidied on the next add), `sale` `{pct (10/20/30/50), until}`, `staffMsg` `{id, text, at, until (+30 min)}`, `gift` `{id, coins <= 100000, gems <= 1000, text, until (15 min / 1 h / 1 day)}`, `mapWeek` `{code, title, by}`. `publicConfig` merges switches + calendar (`liveEvents`): `events` (calendar OR switch), `ends` (when a calendar-only event stops - LiveConfig's `eventOn`/`holiday` ignore an ended one, so the cached answer can't show a finished event), `sale` (biggest active pct). ## Feedback, polls, error reports and alerts (2026-11-13)
- Page: `src/game/PlayerVoice.js`. Server: `api/_lib/inbox.js` via `/api/live` (`feedback`, `vote`, `error`, `contentReport`) and `/api/admin` (`inbox`, `feedbackDone`, `feedbackDelete`, `errorsClear`, `pollStart`, `pollEnd`, `pollDelete`, `alertTest`).
- Feedback = homepage bottom link `#nav-feedback-link` (replaced Settings' "Copy Bug Report"). Bug kind attaches `deviceInfo()`. 5 per Player ID per hour, newest 300 kept.
- Poll = `liveConfig.poll` -> `publicConfig().poll` -> popup once per poll on the homepage (`gayz-polls-seen`). Votes `pollVotes/{id}/{pid}`, once each.
- Errors: window error / unhandled rejection from our own origin only, 5 per visit, off with `shareTelemetry`, never on localhost/webdriver. Grouped in `errors/{sha1(msg|where)}`, digits 4+ long become N.
- Alerts: `DISCORD_ALERT_WEBHOOK` env on the Vercel `gayz` project (new player report, Gallery map report, feedback, new error, error spike at 25/100/500/2000). Max 20 an hour (`alertBudget`), never pings (`allowed_mentions`).
- Down check: `.github/workflows/site-check.yml` every 10 min, same webhook as a GitHub repo secret `DISCORD_ALERT_WEBHOOK`; last state in the Actions cache, saved only on change.

- **Helper accounts and language check (2026-11-13).** `api/_lib/helpers.js`: the owner makes a helper (`helperAdd` -> a one-time password `<6-char id>-<24-char secret>`, only `sha256(secret)` stored at `helpers/{id}`), `helperRemove` stops it at once. Helper-only actions (`helperLogin`, `helperReports`, `helperCheck`) check that password themselves on every call; a helper sees player + map/build reports (no notes/bans) and marks one `real` / `fake` / `none` -> `reportChecks/{p_<id>|map_<id>|build_<id>}` `{verdict, note, by, hid, at}`; `real` also sends the Discord alert. `adminState` returns `checks` + `helpers`; Dismiss clears that report's check. `reportChecks` is in `BACKUP_PATHS`, `helpers` is deliberately NOT (a restore must never bring back a removed helper). `api/_lib/langCheck.js` (`languages` action): every language vs English from `src/game/i18n.js` STRINGS - missing, same-as-English, line-count and `{blank}` mismatches, leftovers; languages under half done only get counts. Privacy Policy's report line mentions helpers. Tests: "helper accounts: login, reports, checks; language check" in `tests/servers.spec.js`.

## Owner drop-in, live map and Hall of Fame (2026-11-13)

- Owner drop-in (`src/game/OwnerDropIn.js`): admin action `dropIn` makes a pass in RTDB `dropTickets/{32 chars}` { serverId, mode 'own'|'ghost', until = 6 h } and returns `/?join=ID&drop=PASS`. `ServerBrowser.joinFromLink` strips both from the address bar and passes `drop` to `/api/servers/join`; `servers.js joinServer` checks it (admin.js `dropTicket`), skips ban/switched-off/full/locked, and marks the player `own` or `ghost`. PlayNet keeps the pass for `_rejoin` (an owner never re-opens a server; gone = lost).
- `own`: others get `own: 1` in sync -> `ownerTag` (gold OWNER + name) + `ownerCrown`. `survival.ownerMode` blocks `_hurtPlayer`; BuildTryMode flies (Jump up / Crouch down at OWNER_FLY, hover otherwise).
- `ghost`: never in anyone's `players`, not counted in lists/full checks, not in serverPids/skins/admin Players; its edits, hits and chat bubbles are dropped server-side; only becomes host when no real player is left (a ghost host gives way to the first real player's sync). Starts in Spectate's free camera.
- Live map: admin action `liveMap` (every server with a real player: players x/y/z in blocks, host/own/ghost/away/dead, kills, Player ID; up to 300 zombies [x, z, boss]).
- Hall of Fame (`src/game/HallOfFame.js`): RTDB `hallOfFame/{8 hex}` { name, title, date YYYY-MM-DD, icon (HOF_ICONS - keep admin.js and HallOfFame.js ICON_SVG in step), pid, skin (64-wide PNG data URL <= 40 KB), order, at }. Admin actions hof / hofSave / hofRemove / hofMove / hofSkin (reads only `data.gayz-settings` from the player's `saves/{uid}` via firestoreRest `skinByPid`). Players: `/api/live { action: 'hof' }` (no Player IDs), cached 5 min. Shown in `#hof-panel` (homepage link) and General's Hall of Fame tab; cards reuse `.home-x-card`. In backups (BACKUP_PATHS).
