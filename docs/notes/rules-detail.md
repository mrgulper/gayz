# Standing rules - full text

Moved out of CLAUDE.md on 2026-10-16 (word for word) so it is only read when needed. Newest notes for a topic go at the end of its file.

- Every completed update gets committed, pushed to GitHub (`mrgulper/gayz`, private), and deployed to Vercel production (`npx vercel --prod --yes` → `gayz.vercel.app`) without asking each time.

- **Panel URLs need no per-route setup (2026-10-01).** `vercel.json` has ONE catch-all rewrite (`/((?!api/).*)` -> `/index.html`; Vercel serves real files first, so assets are unaffected). It used to list every panel path by hand (`/store`, `/inventory`...), and every new panel added to `_bindPanelRouting` without a matching line 404'd on refresh (reported on `/market`). Don't go back to a per-route list.

- **Never leak the owner's GitHub username or AI/tooling names to the public Discord `#updates` feed** (2026-09-30 report). `.github/workflows/discord-update-notify.yml` posts every push to `main`; it used to post the raw first line, which for a merged PR is GitHub's `Merge pull request #N from <username>/claude/<branch>`. It now posts the PR title instead, skips branch-sync merges, and scrubs `mrgulper`/`gulper`/`claude`/`anthropic` words - don't undo that. On top of it: PR titles and commit titles are player-facing patch notes (plain description of the change, no username, no "Claude"/"AI"), and when merging a PR set the merge commit title to the PR title itself (`commit_title`) rather than GitHub's default.

- For batched/greenlit feature work, build straight through without stopping for confirmation checkpoints between items.

- **Finish every update fully in one go - no background tasks (standing rule, 2026-10-10, Gaymi: "next time can you just fully finish instead of this 1 running task thing ... dont make 1 running task just fully finish it").** Run the test suite and every other long step in the foreground (a Bash call with a long `timeout`, e.g. `CI=1 npx playwright test` with `timeout: 600000`), never `run_in_background` or a Monitor, and don't end the turn until the work is tested, merged and pushed. If a step outlasts one call's timeout, keep calling in the foreground until it's done.

- **Everything new is made for every theme (standing rule, 2026-10-10, Gaymi: "add to your memory: everything you make needs to be made for all themes").** Any new or changed UI - panels, buttons, cards, HUD, inputs, the skin designer, even small controls like checkboxes - gets its look for **both** the Old theme (`html.ui-theme-old`: paper, dark ink `--old-ink`, browns/bronze, Rye) and the Golden theme (dark panels, gold `--ui-gold-bright`), checked with a screenshot in each before shipping. Never style one theme and leave the other on a default that doesn't fit (dark boxes on the Old paper, light-on-light text, etc.); a request phrased about one theme still means checking the other doesn't break.

- **Every search bar looks like the Settings search (standing rule, 2026-10-01).** Give any new search input `class="nickname-input search-bar"` (dark fill, thin gold border, pill shape, centered on its own line - see `.search-bar` in `style.css`) and only override width/margin per box, never the colors/border/shape. All existing ones (Settings, Achievements, GayZ Features, Inventory skins, emoji picker, Market) already use it. Since 2026-10-02 the same oval shape also goes on text boxes and dropdowns next to them (chat boxes, Add a Friend, Status picker, Achievements Category/Sort, clan invite - pill block at the end of `style.css`): give any new input/dropdown `border-radius: 999px` too.

- **Patch Notes must always be updated with the game (standing rule, 2026-10-04).** Every player-facing update adds its bullets to the newest entry in `#changelog-list` (a new `vX.YY · Mon D, YYYY` entry for a new day) in the same change - it's hand-written HTML like GayZ Features, and it silently stopped at v0.06 (Sep 29) for five days of updates until Gaymi noticed; v0.07-v0.11 were back-filled from the git history.

- **Patch Notes dates are the owner's local date, not the server's (standing rule, 2026-10-10, Gaymi: "why is it v0.16 when its only my time at around 10pm").** Gaymi is in Cupertino (America/Los_Angeles); sessions run on UTC, which is already "tomorrow" there from 5pm. Before adding or starting a Patch Notes entry, check `TZ=America/Los_Angeles date` and use that day - a new `vX.YY` entry only when it's a new day *there*. (2026-10-12: Gaymi's own screenshots showed a Mac clock about 3 hours ahead of Los Angeles - Mon Oct 12 12:00 AM while LA was still Oct 11 9pm - so v0.17 was started on the date their screen showed. When a screenshot shows their clock, that date wins; otherwise use LA.)

- **Patch notes format (What's New, `#changelog-list` in `index.html`, 2026-10-02).** Each entry is `<div class="changelog-entry"><span class="changelog-date">vX.YY · Mon D, YYYY</span><div class="changelog-text">` + one `<div class="changelog-group changelog-added|changelog-changed|changelog-fixed"><span class="changelog-group-label">Added|Changed|Fixed</span><ul><li>...</li></ul></div>` per kind that has items (in that order) + `</div></div>` - one short bullet per change, never one long paragraph (Gaymi: "everything jammed up"). The panel heading is "Patch Notes" (`buildVersionLine`). Removals go under Changed.

- **The Map Editor picker** has the oval search bar and a block-type dropdown beside it, inside the picker's frame (`PICKER_CATEGORIES`/`_blockCategory` in `BuildMode.js`: Special first - just the Invisible Block for now, and Special blocks also lead the All list via `PICKER_TYPES_SORTED` - then Wood, Stone, Ores & Metals, ..., Slabs, Stairs, Doors/Fences/Ladders). A new block lands in a category by its id; check it isn't in the wrong one. Stairs icons are drawn as stairs (`stairsIconURL` in `BlockTextures.js`).

- **Every block gets a slab AND stairs (standing rule, 2026-10-03).** Any new full block added to `BLOCK_TYPES` (`BuildMode.js`) automatically gets `${id}slab` and `${id}stairs` from the two generator loops right after the list (`slabOf`/`stairsOf` = source id, textured from it via `_shapedSource`) - don't skip them or add a block in a way that bypasses those loops (only water/lava and the hand-named slab/stairs sources are left out). Give every new block its own painter in `BlockTextures.js`'s `BY_ID` (or a matching regex fallback like `terracotta$`/`stainedglass$`) rather than the generic pattern fallback. Stairs face the way you look when placed, like Minecraft (`_stairFacing`, 0 +z / 1 +x / 2 -z / 3 -x, the side the high step is on; saved as `facing` only when non-zero - riding the slot format's door list - so old stairs load as 0; carried in undo `state`).

- **Hand-written player pages are enforced, not remembered (2026-10-04, root-cause fix after both GayZ Features and Patch Notes silently fell days behind).** `scripts/check-docs.mjs` runs as a git `commit-msg` hook (`.githooks/`, wired up by `npm install`'s `prepare` -> `scripts/install-hooks.mjs` setting `core.hooksPath`) and as a CI step on every PR: any commit touching `src/`, `public/` or `index.html` must also edit Patch Notes (`#changelog-list`) **and** GayZ Features (`#features-main`) - both regions end in an `<!-- end ... (scripts/check-docs.mjs) -->` comment the script looks for, keep them - or carry `[no-notes: <why>]` / `[no-features: <why>]` in the commit message **body** (never the title, which goes to Discord). The reason is required (a bare `[no-notes]` fails) so a skip is a written decision someone can question; no script can judge whether the reason or the page's wording is actually right, so still read the entry you're touching. Don't bypass with `--no-verify`. **Nothing countable is typed into GayZ Features by hand:** heading counts are `<span data-feature-count="key">` (`_featureCounts()`), numbers inside descriptions are `<span data-feature-value="key">` (`_featureValues()` - mastery kills, crate prices, timers, the grapple key, languages...), and the expandable lists are **built entirely from code** by `_syncFeatureLists()` from `_featureCatalogs()`: each entry's name and one-line description live next to the thing itself - `about` on `WEAPONS`/`MELEE_VARIANTS` (`WeaponSystem.js`), `ZOMBIE_TYPES`, `NIGHT_EVENTS` (with `name`), `ITEM_INFO` in `Inventory.js`, `MUTATOR_INFO`/`GAME_MODE_INFO` in `Game.js` (`about` may be a function when it names a game constant) - so a new weapon/zombie/item/mutator shows up automatically and one without a description fails the test (`data-missing`). Only `data-extra` items with no single thing in code (Weekly Featured Mutator) are typed in `index.html`. `check-docs.mjs` fails on any digit left in `#features-main` outside those spans (names like AK-47 or Map 3 go in its `ALLOWED_NUMBERS`; `node scripts/check-docs.mjs --page` checks just that), and `tests/docs.spec.js` fails on any `data-auto`/hidden list item, an unknown value/count key, an unfilled `{placeholder}` in How to Play, a rebound key not showing up in text, and any Map Editor pause-screen shortcut (`BuildMode.MENU_SHORTCUTS`) that doesn't do its job when pressed - a new shortcut needs an entry in that test's `CHECKS`.

- **Hand-written sentences are tied to the code they describe (2026-10-04).** A script can't tell whether a sentence is still true, but it can tell when the code behind it changed: every live GayZ Features entry has `data-code="identifiers"` (functions/constants that implement it), and each How to Play step (`HOWTOPLAY_STEPS`, Game.js) and Map Editor pause tip (`MENU_TIPS`, BuildMode.js) has `code: '...'`. `check-docs.mjs` fails when a change adds/removes a non-comment line using one of those identifiers without editing that text in the same change - name it with `[reread: <entry title or text key>]` in the commit message after actually re-reading it. It also fails on a live entry with no `data-code` and on a linked identifier that no longer exists in `src/` (removed or renamed - fix the text and the link). Pick distinctive identifiers (a constant or function used only by that feature), not ones every commit touches. `code: ''` is allowed for text with no gameplay behind it (htpRules). The typed-key check also covers wordings like "hit F", "the F key", "tecla F", "按F键", `[F]`, `<kbd>` (letters stay case-sensitive so "needs a key" isn't flagged), and scans string literals in code, not only i18n.js.

- **No key letter is ever typed into player text (2026-10-04).** Every string names keys as `{key:<id>}` (`**{key:interact}**`, `{key:healthPack}`, `{key:move}` for all four movement keys) and `i18n.js`'s `interpolate` fills in the player's real key through the lookup `Keybinds.js` registers (`setKeyNameLookup`): a rebindable `ACTIONS` id, a `HOTBAR_ITEM_SLOTS` id, or a `FIXED_KEYS` id (non-rebindable keys - inventory Tab, the Map Editor's T/M/V - which the handlers also read, so text and behavior can't differ). This replaced ~240 typed letters across all languages after "press H to use" outlived the move of Health Packs to hotbar slot 4, and the upgrade machine/mystery box said "Press E" for an F action. `check-docs.mjs` fails on a typed key in en/zh/hi/es text and on a `{key:...}` id Keybinds.js doesn't know.

### Standing rules (full text in `docs/notes/rules-detail.md`)

- **Ship every update fully:** commit, push to `mrgulper/gayz`, open a PR, merge only once lint/build/tests are green (CI or, while CI is off, locally - see "Which tests to run"), merge commit title = PR title. Build greenlit batches straight through without checkpoints, as **one** build, test run and PR per batch (related requests sent together are one PR, not several).
- **No background tasks.** Run long steps (the test suite) in the foreground with a long timeout; don't end the turn until it's tested and merged.
- **Public text never names the owner or AI tools.** PR and commit titles go to the public Discord `#updates` feed: plain player-facing descriptions, no username, no "Claude"/"AI". Don't undo the scrubbing in `.github/workflows/discord-update-notify.yml`.
- **Patch Notes (`#changelog-list` in `index.html`) and GayZ Features (`#features-main`) are updated in the same change as every player-facing update.** Patch Notes: newest `vX.YY · Mon D, YYYY` entry, dated by `TZ=America/Los_Angeles date` (or the date on Gaymi's screenshot clock); groups Added / Changed / Fixed, one short bullet per change. GayZ Features: new features get a `<div class="feature" data-code="...">`, changed ones get fixed; no hand-typed numbers (use `data-feature-value`/`data-feature-count` spans); when code linked by `data-code` changes, re-read the entry and name it with `[reread: <title>]` in the commit body. Skips need `[no-notes: why]` / `[no-features: why]` in the commit body.
- **Every Coming Soon spot in the game has a GayZ Features Coming Soon entry** (and a line in `tests/docs.spec.js`'s `MAP`).
- **Every new i18n key ships in `en`, `zh`, `hi` and `es` together.** Player text never types a key letter - use `{key:<id>}`.
- **Every UI change is made for both themes** (Old: paper, dark ink, browns, Rye; Clean: flat, one colour the player picks - Golden was deleted 2026-10-23) and checked with a screenshot in each - only when something visible changes; code-only changes need no screenshots.
- **Search bars** use `class="nickname-input search-bar"`; text boxes and dropdowns are ovals (`border-radius: 999px`).
- **Panels:** every panel and tab is the same height (`min-height: calc(68vh + var(--panel-chrome))`), nothing scrolls sideways, and new panels join the shared selector list in `style.css`.
- **Homepage:** its first paint is its final look (layout fitters in `index.html`'s inline `__menuLayout`, first-screen pictures in `src/menu-art/`); footer links stay clear of the right column; homepage animations run on `LiteHome.onHomeFrame` and never animate `background-position`, `filter` or a blended layer.
- **The nameplate** (level, name, clan) is the same `.nameplate` filled by `Game._fillNameplate()` on the homepage character and in Inventory.
- **Map-making** (`Map3Generator.js`, any generated map): only existing `BLOCK_TYPES`; nothing "squared" or on a street grid; uneven ring of edge buildings; no ruined buildings; liquids sealed; ladders against walls; sloped roofs only on whole rectangles at half a block per cell; every building enterable and climbable; check it automatically (walking flood fill, ladders, water) and by flying the camera. Changing the generator = bump `MAP3_EDITS_KEY`. Full 10 rules in `rules-detail.md`.
- **Every standing mob is 2 blocks tall** (`MOB_HEIGHT` in PlayRules.js, bloxd.io's size) - zombies, skeletons, player bodies, NPCs and any mob added later.
- **The underground is implicit** (`Underground.js`): rock below each column's bottom is never stored whole - only seen cells (cave walls, entrance walls, neighbours of broken blocks) become blocks. Never fill it in bulk.
- **Every new full block gets a slab and stairs** (generated by the loops after `BLOCK_TYPES`) and its own painter in `BlockTextures.js`.
- **New GLBs** go through gltf-transform (small textures, meshopt) before committing; list makers in `public/models/weapons/CREDITS.txt` only - the in-game Credits page no longer lists 3D models (Gaymi, 2026-10-17).
- **Panel URLs:** `vercel.json` has one catch-all rewrite - never a per-route list.
- **Split `Game.js` and `style.css` bit by bit (standing rule, 2026-10-16, Gaymi: "do it bit by bit").** Whenever an update works in an area of `Game.js` (Settings, Clans, Profile, Friends, Market, Upgrades...), first move that area into its own module the usual way (plain functions taking `game`, state stays on `game` - see `docs/notes/codebase.md`), as a pure move in its own commit before the feature change, checked with lint + build + the tests for that area. `python3 scripts/move-to-module.py NewModule.js "header comment" _method1 _method2 ...` does the move mechanically (one-line stand-ins stay in Game.js so callers are unchanged; imports/exports are wired up); `check-docs.mjs` recognises moved lines, so a pure move needs only `[no-notes: ...]`/`[no-features: ...]`, no `[reread: ...]`. `style.css` and `i18n.js` were split in one go on 2026-10-30 at Gaymi's request (pure moves, built CSS byte-identical) - see `codebase.md`. Otherwise never a big all-at-once split, never a move mixed into a behaviour change.
- **Don't ship inert UI.**
- **Everything single player works offline** (service worker `src/sw.js`, `Offline.js`): load files from the game itself, never a CDN; new online-only buttons go in `ONLINE_ONLY` (+ `offline.css`). Details in `docs/notes/online.md`.
- **Old Map 1 is gone for good** - new Map 1 features are built for the block-city engine (`BuildSurvival`/`BuildCamp`), never by bringing back old code.

### Most common traps (details in `docs/notes/bugs-and-testing.md`)

- Clone materials per instance before flashing/recolouring them.
- Never add, remove or toggle a `THREE.Light` at runtime - the block world has no point lights (glow is baked vertex light).
- Nothing in the per-frame path writes to `localStorage`.
- Treat every persisted value as untrusted in `innerHTML` (`_escapeHtml`, `_safeStatNumber`) - Import Save exists.
- `game.gameStarted` is never true now: use `_showHomepageToast`.
- Cloud Save is a three-way merge; automatic syncs are upload-only - never add an automatic apply/reload.
- Open-world terrain can only hold full cube blocks (no ladders, slabs, fences, doors).
- In Playwright: wait for `window.__game` with a poll loop; keep timing-sensitive checks in one `evaluate()`; `pkill -f chromium` in its own command, never chained with other commands.
