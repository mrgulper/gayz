# Homepage features and menu fixes

Split out of the old `ui-and-menu.md` on 2026-11-13 (word for word, oldest first). Add new notes at the end.

- **Clicking the homepage while a panel is open (2026-10-10).** The footer links (`#menu-links-row`, z-index 16) sit above the panels' backdrop (15), so they open their page directly. The right column can't be lifted that way (it's inside `#menu-layout`'s own z-index 1 layer with the hero), so a capture-phase document click listener in Game.js turns a backdrop click that lands on a `#menu-nav-buttons` button or `#menu-player-badge` (`document.elementsFromPoint`) into a click on that button; a click anywhere else on the backdrop still closes the panel. Credits is two tabs (`.credits-tab`, styled with `.general-tab`'s rules - its own class because the General panel's handler grabs every `.general-tab`). The Old theme close X is ink brown (`#4a2c10`), Golden keeps red; the Old Game Mode plate is 180px wide.

- **Play fades, homepage water, footer links, tab icon (2026-10-10).** Play (`_enterBuildMode({ play: true })`, homepage and server joins) fades `#play-fade` to black (`_fadeScreen(1)`, `PLAY_FADE_MS`), does the heavy part (loading BuildMode, generating Map 1, `enter`, `survival.start`) behind it, then fades back after two drawn frames - Gaymi: "make it just slowly fade when it's loading instead of making the page lag". The homepage road (`MenuWater.js`) no longer redraws the photo shifted (that moved the cobbles - "the road is moving"): the photo stays still and the canvas (`mix-blend-mode: screen`) draws a blurred copy of only the bright wet sheen (`makeSheen`, alpha from brightness), shifted and brightened by waves. Footer links (`#menu-links-row`) have no underline, `user-select: none` and no focus ring - hover/focus only brightens; every `button` is `user-select: none`. The tab icon is the GayZ face, flat (`public/favicon-64.png`/`-32.png`/`apple-touch-icon.png`, cropped from Gaymi's picture - its checkerboard was painted in, so only the face square is kept; `favicon.svg` is gone) - the quest badge (`_updateFaviconQuestBadge`) draws on top of whatever `link[rel=icon]` holds. Friend List: `_renderFriendsCount` shows "Your Friends (n)"; a friend request is create-only in the rules, so sending again while one is waiting is `permission-denied` - `_sendFriendRequestTo` says `friendRequestAlreadySent` for that, and `friendAlreadyFriend` for someone already on the list - `_findSavedFriend` matches by uid, #ID or case-insensitive name, and `_sendFriendRequestClick` checks it before any lookup instead of the generic Cloud Save error. Design a Skin's stacked (<=600px) rule must stay *after* the base `.stage` rule in `public/skin-designer/index.html` - placed before it, the preview stayed sticky and the tools scrolled over it. The Global chat box ends higher than the server list (`#server-panel-columns #server-chat-wrap` `height: auto` + bottom margin). Inventory's cards (`.inv-skin-card` - character, weapon and Market cards) follow the theme: dark warm brown with a gold rim in Golden, a darker patch of paper with a brown rim and ink lettering (and ink placeholder icons) in Old - they were navy boxes.

- **Homepage shortcuts (`MenuEasterEggs.js`: R reopens the last panel, ?, Escape) skip both a running game and the Map Editor** (`game.buildMode.active`) - R used to reopen Game Mode on top of the editor (2026-10-03).

- **Patch Notes go live at the player's own midnight; the What's New card is top-right and never ahead of What's New (2026-10-12).** `Game._gateChangelog()` parses each entry's `Mon D, YYYY`, hides (`.changelog-future`) any whose local midnight hasn't come yet and re-runs itself at the next local midnight; the digest and the update card only read `.changelog-entry:not(.changelog-future)`. `_checkForUpdate` copies the new build's whole `#changelog-list` into this page before showing the card (the card used to show the new version while What's New still had the old one). `#update-available-banner` sits at the very top-right corner (`top`/`right` 12px, z-index 17, over the profile card). The homepage clock was already the device's local time; its tooltip now names the time zone. Big map: in the middle size (`MAP_SIZES` 'center') the minimap is interactive (`_mapInteractive`, pointer lock released, `.interactive`): drag pans (`_mapPan`), wheel zooms (`zoomMap`, `MAP_MIN_SPAN`..`MAP_MAX_SPAN`), double-click recentres, `#build-try-map-hint` says so (`mapDragHint`); cycling away resets it and re-locks the mouse.

- **2026-10-12 batch.** The homepage character (`#setup-avatar-wrap`) is sized by window height (`clamp(240px, 54vh, 620px)` x `clamp(115px, 26vh, 298px)`) - the old fixed 345x720 with 504/270 height tiers jumped to full size past 960px tall (MacBook full screen). Measured ~60-100ms per resize event on a 4x-throttled phone before. **Points:** the blue star shows `metaProgress.legacyPoints` (the Upgrades currency, player text says "Points" everywhere - the storage field keeps its old name); it used to show `this.points`, the last run's score. - **Homepage rain and the What's New card (2026-10-09).** The rain is a canvas (`#menu-bg-rain`, drawn by `MenuRain.js`, started from `main.js` before the game loads): rain falls **from the very top of the page and lands only on the street** (Gaymi, same day: "only on the floor ... straight not sideways ... hard and softly as time goes ... don't just use lines", then "make it rain from the very top" - drawing only the last part of each fall made it look like it started halfway down): each drop picks a landing spot inside `FLOOR` (fractions of the photo - both themes' photos share the framing - mapped through the CSS's `cover` / `center 35%`, so change those together) and splashes there, smaller/slower the farther up the street; no wind; strength eases between drizzle and downpour (`INTENSITY_*`, only the first `intensity` share of the drop pool falls); drops are a pre-drawn sprite (`dropSprite`, lit head + fading tail), splashes are a crown, droplets and two ripple rings; it sits in front of the fog/scrim/vignette layers, draws only while it has a layout box (homepage visible, Weather Particles on) and the tab is visible, nothing under prefers-reduced-motion, half the drops under Reduce Homepage Background Effects. **The road's water moves** (`MenuWater.js`, 2026-10-09, "make the water on the road actually moving"): `#menu-bg-water` is a canvas *inside* `#menu-bg-photo` (so it gets the Ken Burns transform and mood filter for free) that redraws only the street (clipped to the same `FLOOR` shape, `pictureBox()` exported from MenuRain.js) in `ROW_PX` rows nudged sideways by waves running down the road, stronger near the bottom and in heavy rain (`rainState.intensity` from MenuRain); the picture is read from the photo's own computed `background-image`, so it follows the theme. Homepage lettering: the right-side button labels and `#menu-subtitle` were switched to the theme's display font + gold the same day and switched straight back to the plain white sans-serif at Gaymi's request ("change it back ... back to white too") - don't restyle them that way again. `#gamemode-btn`'s plate is padded a fifth bigger (19px 64px). - A 17-feature homepage batch ("add all to the homepage") added real UI to `menu-col-left`/`menu-col-right`/hero (Continue card, Recommended Difficulty hint, Loadout Presets row, Achievement Showcase row, Season Progress bar, Spotlight ticker) and blew the zero-scroll budget by ~90px at the 900px-tall heights and ~90px at 768px, even though 1920x1080 stayed at 0px overflow the whole time (it already had slack; 900px/768px never do). Fixing it needed two different levers because the two height tiers were short on different things: at 900px, `.menu-card-list`'s existing single `@media (max-height: 820px)` gate didn't apply at all (900 > 820), so a **second, looser gate** was added above it (`@media (max-height: 960px) { .menu-card-list { max-height: 15vh } }`, source-ordered *before* the existing 820px/tighter one so the tighter rule still wins at heights under both) - that alone closed 900px down to 3px, finished off with a 3px trim to `#menu`'s own top padding (`6px`→`3px`, safe globally since 1080 already had slack). At 768px the card-list cap was already maxed out (5vh, barely any content left to shrink) so further gains had to come from the *fixed-px* new content instead: the existing 820px breakpoint now also hides `#menu-spotlight`/`.menu-preset-row`/`#achievement-showcase-row` entirely and tightens `#menu-col-left`/`-right` gap (`9px`→`6px`) and `.menu-panel` padding (`8px 14px`→`6px 12px`) - same "genuinely short windows lose the nice-to-haves first" precedent as `#round-mode-hint`/`#controls-list`. Lesson for next time: a batch that adds several small elements across *multiple* columns is deceptively expensive, because `#menu-layout`'s row height is the *tallest* column, not the sum - estimate cost per-column, not per-feature, before assuming small individual additions are safe.
